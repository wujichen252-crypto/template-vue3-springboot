# Gradle + Kotlin DSL 最佳实践文档

> **适用场景**：Spring Boot / 纯 Kotlin / Java 后端项目  
> **核心工具**：Gradle 8.x + Kotlin DSL (`build.gradle.kts`)  
> **归档编号**：Gradle-KotlinDSL-BestPractice-001

---

## 一、为什么选 Kotlin DSL

| 维度           | Groovy DSL (`build.gradle`)      | Kotlin DSL (`build.gradle.kts`)      |
| -------------- | -------------------------------- | ------------------------------------ |
| **类型安全**   | ❌ 动态类型，拼写错误运行时才暴露 | ✅ 静态类型，IDE 实时报错             |
| **IDE 补全**   | ⚠️ 有限，基本靠记忆               | ✅ 完整的代码补全、参数提示、文档跳转 |
| **重构支持**   | ❌ 重命名/提取变量基本不可用      | ✅ 全套 IDE Refactor 支持             |
| **语法一致性** | 与 Kotlin/Java 代码风格割裂      | 与 Kotlin 后端代码风格统一           |
| **官方推荐**   | 兼容维护                         | ✅ Spring Initializr 默认首选         |

**结论**：新项目无脑选 Kotlin DSL；老 Groovy 项目迁移成本不高，建议逐步切。

## 二、项目初始化标准流程

### 2.1 通过 Spring Initializr 创建

访问 [start.spring.io](https://start.spring.io)，选择：

- **Project**：Gradle — Groovy / Kotlin 选 **Kotlin**
- **Language**：Java / Kotlin（根据项目选）
- **Spring Boot**：3.2.x+（要求 Gradle 8.5+）

生成后核心文件结构：

```text
project-root/
├── build.gradle.kts              # 根项目构建脚本
├── settings.gradle.kts           # 项目结构声明
├── gradle/
│   ├── libs.versions.toml        # 版本目录（Version Catalog，强烈推荐）
│   └── wrapper/
│       ├── gradle-wrapper.jar
│       └── gradle-wrapper.properties
├── gradlew / gradlew.bat         # Wrapper 脚本（提交到 Git）
├── src/...
└── gradle.properties             # 全局属性（JVM 参数、版本号等）
```

### 2.2 手动初始化（非 Spring Boot 场景）

```bash
# 1. 初始化 Kotlin DSL 项目
gradle init --type kotlin-application --dsl kotlin

# 2. 或先创建空项目再生成 Wrapper
gradle wrapper --gradle-version 8.7
```

## 三、核心文件详解

### 3.1 `settings.gradle.kts` —— 项目入口

```kotlin
rootProject.name = "neuramind-backend"

// 多模块时声明子模块
include("app", "domain", "infrastructure")

// 启用版本目录（Version Catalog）
dependencyResolutionManagement {
    repositories {
        mavenCentral()
        maven { url = uri("https://maven.aliyun.com/repository/public") } // 国内加速
    }
}
```

### 3.2 `build.gradle.kts` —— 根项目配置

```kotlin
plugins {
    java
    id("org.springframework.boot") version "3.2.5"
    id("io.spring.dependency-management") version "1.1.4"
    kotlin("jvm") version "1.9.23"
    kotlin("plugin.spring") version "1.9.23" // 开启 all-open，解决 Kotlin + Spring AOP 问题
}

group = "com.neuramind"
version = "1.0.0"

java {
    sourceCompatibility = JavaVersion.VERSION_17
}

repositories {
    mavenCentral()
    maven { url = uri("https://maven.aliyun.com/repository/public") }
}

dependencies {
    implementation("org.springframework.boot:spring-boot-starter-web")
    implementation("org.springframework.boot:spring-boot-starter-data-jpa")
    
    // Kotlin 专属
    implementation("com.fasterxml.jackson.module:jackson-module-kotlin")
    implementation("org.jetbrains.kotlin:kotlin-reflect")
    
    testImplementation("org.springframework.boot:spring-boot-starter-test")
}

tasks.withType<Test> {
    useJUnitPlatform()
}

// Kotlin 编译选项
tasks.withType<org.jetbrains.kotlin.gradle.tasks.KotlinCompile> {
    compilerOptions {
        freeCompilerArgs.add("-Xjsr305=strict")
        jvmTarget.set(org.jetbrains.kotlin.gradle.dsl.JvmTarget.JVM_17)
    }
}
```

### 3.3 `gradle.properties` —— 全局 JVM 与构建优化

```properties
# Gradle 守护进程优化
org.gradle.jvmargs=-Xmx2048m -Dfile.encoding=UTF-8
org.gradle.parallel=true
org.gradle.caching=true
org.gradle.configureondemand=true

# Kotlin 守护进程复用
kotlin.daemon.jvmargs=-Xmx2048m
```

## 四、依赖管理最佳实践

### 4.1 配置类型（Scope）选择

| 声明方式                  | 传递性                   | 使用场景                                                     |
| ------------------------- | ------------------------ | ------------------------------------------------------------ |
| `implementation(...)`     | 不对外暴露               | **默认首选**。内部使用的库，如数据库驱动、工具类             |
| `api(...)`                | 会传递给依赖本模块的模块 | 本模块的公开 API 中暴露了该库的类型，如 `public List<GuavaClass> method()` |
| `compileOnly(...)`        | 编译期存在，打包排除     | 注解处理器、Lombok、Servlet API（容器提供）                  |
| `runtimeOnly(...)`        | 运行时需要，编译不需要   | JDBC 驱动、日志实现（如 Logback）                            |
| `testImplementation(...)` | 仅测试                   | JUnit、Mockito                                               |

**原则**：能用 `implementation` 绝不用 `api`，避免依赖泄漏导致版本冲突。

### 4.2 Version Catalog（版本目录）—— 强烈推荐

在 `gradle/libs.versions.toml` 中集中管理版本，彻底告别散落在各处的硬编码版本号：

```toml
[versions]
spring-boot = "3.2.5"
kotlin = "1.9.23"
gorm = "8.0.0"  # 举例

[libraries]
spring-web = { module = "org.springframework.boot:spring-boot-starter-web" }
spring-data-jpa = { module = "org.springframework.boot:spring-boot-starter-data-jpa" }
jackson-kotlin = { module = "com.fasterxml.jackson.module:jackson-module-kotlin" }
kotlin-reflect = { module = "org.jetbrains.kotlin:kotlin-reflect" }

# 带版本号的第三方库
guava = { module = "com.google.guava:guava", version = "33.1.0-jre" }

[bundles]
spring-basic = ["spring-web", "spring-data-jpa"]  # 批量引用

[plugins]
spring-boot = { id = "org.springframework.boot", version.ref = "spring-boot" }
kotlin-jvm = { id = "org.jetbrains.kotlin.jvm", version.ref = "kotlin" }
kotlin-spring = { id = "plugin.spring", version.ref = "kotlin" }
```

**在 `build.gradle.kts` 中引用：**

```kotlin
plugins {
    alias(libs.plugins.spring.boot)
    alias(libs.plugins.kotlin.jvm)
    alias(libs.plugins.kotlin.spring)
}

dependencies {
    implementation(libs.spring.web)
    implementation(libs.jackson.kotlin)
    
    // 批量引用
    implementation(libs.bundles.spring.basic)
}
```

**优势：**

- 一处改版本，全局生效
- 支持 IDE 自动补全（`libs.` 开头）
- 多模块项目共享同一套版本定义

## 五、多模块项目配置

### 5.1 典型微服务/DDD 分层结构

```text
neuramind-backend/
├── settings.gradle.kts
├── build.gradle.kts          # 根项目：定义公共插件和约束
├── gradle/libs.versions.toml
├── app/                        # 应用层（启动入口、Controller）
│   └── build.gradle.kts
├── domain/                     # 领域层（纯 Kotlin，无 Spring 依赖）
│   └── build.gradle.kts
├── infrastructure/             # 基础设施（数据库、缓存、消息队列）
│   └── build.gradle.kts
└── shared/                     # 共享工具（常量、异常定义）
    └── build.gradle.kts
```

### 5.2 根项目 `build.gradle.kts`（公共约束）

```kotlin
plugins {
    kotlin("jvm") version "1.9.23" apply false
    id("org.springframework.boot") version "3.2.5" apply false
}

allprojects {
    group = "com.neuramind"
    version = "1.0.0"
    
    repositories {
        mavenCentral()
        maven { url = uri("https://maven.aliyun.com/repository/public") }
    }
}

subprojects {
    apply(plugin = "org.jetbrains.kotlin.jvm")
    
    dependencies {
        implementation(kotlin("stdlib"))
        testImplementation("org.junit.jupiter:junit-jupiter:5.10.2")
    }
    
    tasks.withType<Test> {
        useJUnitPlatform()
    }
}
```

### 5.3 子模块 `app/build.gradle.kts`

```kotlin
plugins {
    application
    id("org.springframework.boot")
}

dependencies {
    implementation(project(":domain"))           // 依赖兄弟模块
    implementation(project(":infrastructure"))
    
    implementation("org.springframework.boot:spring-boot-starter-web")
}
```

### 5.4 模块间依赖原则

- `domain` 模块 **不允许** 依赖任何 Spring / 基础设施库（纯 Kotlin）
- `app` 模块作为组装层，可以依赖所有模块
- 禁止循环依赖：`A -> B -> A`，Gradle 会直接报错阻断

## 六、国内加速与私有仓库

### 6.1 阿里云镜像（必配）

在 `settings.gradle.kts` 或根 `build.gradle.kts` 中：

```kotlin
repositories {
    mavenCentral()
    maven { url = uri("https://maven.aliyun.com/repository/public") }
    maven { url = uri("https://maven.aliyun.com/repository/spring") }
    maven { url = uri("https://maven.aliyun.com/repository/gradle-plugin") }

```

### 6.2 私有仓库（Nexus / GitLab Package）

```kotlin
repositories {
    maven {
        url = uri("https://nexus.company.com/repository/maven-releases/")
        credentials {
            username = findProperty("nexusUsername")?.toString() ?: System.getenv("NEXUS_USER")
            password = findProperty("nexusPassword")?.toString() ?: System.getenv("NEXUS_PASS")
        }
    }
}
```

```bash
# 构建时强制校验锁定文件
./gradlew build --refresh-dependencies
```

## 七、构建任务与日常命令

### 7.1 常用命令速查

```bash
# 初始化 / 查看
./gradlew tasks                   # 列出所有可用任务
./gradlew dependencies            # 查看依赖树（排查冲突神器）
./gradlew dependencies --configuration compileClasspath

# 构建
./gradlew build                   # 完整构建（编译 + 测试 + 打包）
./gradlew build -x test           # 跳过测试
./gradlew clean build             # 清理后重新构建

# 运行
./gradlew bootRun                 # Spring Boot 直接运行
./gradlew bootRun --args='--spring.profiles.active=dev'

# 测试
./gradlew test                    # 运行所有测试
./gradlew test --tests "com.example.*ControllerTest"

# 格式化 / 检查
./gradlew ktlintCheck             # Kotlin 代码风格检查（需插件）
./gradlew ktlintFormat            # 自动格式化
```

### 7.2 构建优化参数

```bash
# 并行构建 + 守护进程 + 构建缓存
./gradlew build --parallel --build-cache --daemon

# 配置按需（多模块时只配置改动的模块）
./gradlew build --configure-on-demand
```

## 八、CI/CD 集成规范

### 8.1 GitHub Actions 缓存配置

```yaml
- name: Setup Gradle
  uses: gradle/actions/setup-gradle@v3
  with:
    gradle-version: 8.7

- name: Cache Gradle dependencies
  uses: actions/cache@v4
  with:
    path: |
      ~/.gradle/caches
      ~/.gradle/wrapper
    key: ${{ runner.os }}-gradle-${{ hashFiles('**/*.gradle.kts', '**/gradle.properties', '**/libs.versions.toml') }}
    restore-keys: ${{ runner.os }}-gradle

- name: Build
  run: ./gradlew build --no-daemon
```

### 8.2 Docker 多阶段构建

```dockerfile
# 阶段一：依赖缓存层
FROM gradle:8.7-jdk17-alpine AS deps
WORKDIR /app
COPY gradle/ gradle/
COPY gradlew build.gradle.kts settings.gradle.kts gradle.properties ./
COPY gradle/libs.versions.toml gradle/
RUN ./gradlew dependencies --no-daemon

# 阶段二：编译
FROM gradle:8.7-jdk17-alpine AS builder
WORKDIR /app
COPY --from=deps /home/gradle/.gradle /home/gradle/.gradle
COPY . .
RUN ./gradlew bootJar --no-daemon

# 阶段三：运行
FROM eclipse-temurin:17-jre-alpine
COPY --from=builder /app/build/libs/*.jar app.jar
ENTRYPOINT ["java", "-jar", "/app.jar"]
```

## 九、Kotlin DSL 语法要点

### 9.1 与 Groovy 的关键差异

| 场景        | Groovy                     | Kotlin DSL                                       |
| ----------- | -------------------------- | ------------------------------------------------ |
| 字符串      | 单双引号都行               | **必须双引号**                                   |
| 函数调用    | `id 'java'`                | `id("java")`                                     |
| 赋值        | `version = '1.0'`          | `version = "1.0"`                                |
| 闭包/配置块 | `config { option = true }` | `config { option.set(true) }` 或 `option = true` |
| 类型强转    | 自动                       | 显式：`the<SourceSetContainer>()`                |

### 9.2 获取属性

```kotlin
// 从 gradle.properties 或命令行 -P 参数
val profile: String by project
val customValue = findProperty("customKey")?.toString() ?: "default"
```

### 9.3 条件逻辑

```kotlin
tasks.register<Copy>("customCopy") {
    onlyIf { project.hasProperty("enableCopy") }
    from("src")
    into("dest")
}
```

## 十、常见问题排查手册

| 现象                                             | 根因                              | 解决                                                         |
| ------------------------------------------------ | --------------------------------- | ------------------------------------------------------------ |
| `Could not find method implementation()`         | 误用 Groovy 语法在 Kotlin 文件    | 确认文件后缀是 `.kts`，且语法为 `implementation("...")`      |
| `Unresolved reference: libs`                     | Version Catalog 未启用            | 检查 `settings.gradle.kts` 中 `dependencyResolutionManagement` 块 |
| 依赖下载极慢                                     | 未配置国内镜像                    | 在 `repositories` 中添加阿里云镜像                           |
| `Duplicate class` / 版本冲突                     | 传递依赖版本不一致                | `./gradlew dependencies` 查冲突，用 `implementation("xxx") { exclude(group = "yyy") }` 排除 |
| Kotlin 编译报错 `JVM target`                     | JDK 版本与 Kotlin 目标不匹配      | `compilerOptions { jvmTarget.set(JvmTarget.JVM_17) }`        |
| Spring Boot 启动报错 `bean not of required type` | Kotlin 类默认 final，AOP 代理失败 | 应用 `kotlin("plugin.spring")` 插件（自动 all-open）         |

## 十一、依赖排除与强制版本

```kotlin
dependencies {
    implementation("org.springframework.boot:spring-boot-starter-web") {
        exclude(group = "org.springframework.boot", module = "spring-boot-starter-logging")
    }
    
    // 强制指定版本（覆盖传递依赖）
    implementation("com.google.guava:guava:33.1.0-jre") {
        because("修复 CVE-2024-xxxx 漏洞")
    }
}
```

## 十二、团队提交规范

**提交前自检：**

1. `./gradlew ktlintCheck` 或 IDE 自动格式化通过
2. `./gradlew test` 本地全量测试通过
3. `./gradlew dependencies` 检查是否有意料之外的版本变更
4. `gradlew wrapper` 相关文件有变动时，确认 `gradle-wrapper.jar` 和 `gradle-wrapper.properties` 一并提交

**Code Review 关注点：**

- `build.gradle.kts` 中是否出现硬编码版本号？应放入 `libs.versions.toml`
- 新增依赖是否使用了 `implementation` 而非过度宽松的 `api`？
- 多模块项目是否出现 `domain` 层依赖 Spring / 基础设施库？
